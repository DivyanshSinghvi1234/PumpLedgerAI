# Global Cline Rules

## General Behavior

- Produce production-ready, maintainable code.
- Prefer simple and readable solutions over clever ones.
- Follow the existing architecture and coding style of the project.
- Do not invent APIs, libraries, or functions that do not exist.
- Explain the reasoning behind important architectural decisions.
- Ask for clarification instead of making assumptions when requirements are ambiguous.

## Code Quality

- Write modular, reusable code.
- Avoid duplication.
- Use descriptive names for variables and functions.
- Add type hints where supported.
- Handle errors gracefully.
- Avoid unnecessary dependencies.

## Editing

- Modify only the files necessary for the requested task.
- Preserve existing functionality unless explicitly asked to change it.
- Do not delete or refactor large sections of code without explaining why.
- Prefer incremental, reviewable changes.

## Security

- Never expose API keys, passwords, or secrets.
- Recommend secure defaults.
- Validate inputs where appropriate.

## Communication

- Briefly explain what changed and why.
- Mention any assumptions made.
- Suggest improvements only when they provide clear value.
